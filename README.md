Introduction
Financial institutions store important customer and transaction data. The computers and laptops used by employees can become a target for malware, unauthorized access, and data theft. Hence, an endpoint security policy is required to protect these devices.
This portfolio documents a basic endpoint security policy created for a financial institution.endpoint devices are used by employees for daily activities such as accessing internal applications, processing customer information, communicating with other departments, and handling financial records. Because these devices are connected to the organizational network, they must be properly protected. A malware infection or unauthorized access on one endpoint may create a risk to important data. Therefore, endpoint security policies are necessary to define how devices should be used, protected, and monitored. This helps the organization maintain a common level of security for all authorized devices.

Objective
The main objective is to create security rules for endpoint devices and reduce the risk of unauthorized access and cyberattacks.
The policy mainly focuses on:
Antivirus protection
Password and access control
MFA
Software updates
USB control
Data protection
Security monitoring
The objective of this work is to understand the importance of endpoint security and prepare a set of basic security rules suitable for a financial institution. The policy aims to protect devices from common threats and reduce the possibility of unauthorized access. It also focuses on controlling user access, keeping systems updated, protecting sensitive information, and monitoring security-related events. By following these rules, employees and administrators can understand their responsibilities in maintaining endpoint security.

Problem Identified
If employee systems are not properly secured, the following problems may occur:
Malware infection
Weak passwords
Unauthorized software installation
Data leakage through USB devices
Unpatched software vulnerabilities
Unauthorized access to sensitive data
Therefore, a common security policy is needed for all organizational endpoint devices.
Endpoint devices can become vulnerable when proper security controls are not applied. For example, an employee may accidentally open a harmful file, connect an unknown USB device, use a weak password, or install unauthorized software. Outdated systems may also contain security weaknesses that can be exploited. In a financial institution, such issues can affect confidential customer information and normal business operations. The main problem identified is the absence of a common and clearly documented set of security requirements for managing endpoint devices.

Proposed Endpoint Security Policy

The following rules were prepared:
1. Device Registration
All official computers and laptops should be registered and approved by the IT department.
2. Authentication
Users should use strong passwords. MFA should be enabled for important systems. Access should be provided based on the user's role.
3. Antivirus Protection
Approved antivirus or endpoint protection software should be installed and kept active. Regular scanning should be performed.
4. Software Updates
Operating systems and applications should be updated regularly to fix security vulnerabilities.
5. USB Control
Unknown or unauthorized USB devices should not be used. Approved devices should be scanned before accessing the system.
6. Data Protection
Sensitive financial data should be protected. Important laptops should use encryption, especially portable devices.
7. Application Control
Employees should not install unauthorized or pirated software.
8. Security Monitoring
Important events such as failed login attempts and malware alerts should be monitored and reported to the security team.
The proposed policy provides a basic set of rules that can be followed for securing organizational endpoints. It includes requirements for device registration, authentication, antivirus protection, software updates, data protection, application control, USB security, and monitoring. Each employee using an organizational device should follow these requirements. The policy also helps the IT or security team maintain a consistent security configuration. Instead of handling every device differently, the same basic security standards can be applied throughout the organization.The policy should be communicated clearly to all employees so that they understand the security requirements. Users should report any suspicious activity, unknown software, malware alerts, or unusual device behavior to the appropriate IT or security team. The policy should also be reviewed regularly because new security threats and technologies may require changes to the existing rules.

Implementation
For implementing the policy, the following basic steps were followed:
Identified the endpoint devices.
Defined basic security requirements.
Enabled endpoint/antivirus protection.
Checked system update settings.
Applied password and access-control rules.
Restricted unauthorized applications and USB usage.
Checked security alerts and logs.
The implementation was planned as a step-by-step process. First, the available endpoint devices were identified and their basic security requirements were considered. Security settings such as antivirus protection, operating system updates, and access controls were then checked. Unauthorized applications and unnecessary access were restricted based on the policy requirements. After applying the basic controls, security alerts and system logs were reviewed to check whether important events could be identified. This process helps in verifying that the policy requirements are not only documented but can also be applied in practice.
